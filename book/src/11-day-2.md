# Day-2 operations

## Changing a setting

Edit the overlay, commit, push, and **Sync**. `bnk up` runs `terraform plan`
against the applied state and applies only the difference. Settings roksbnkctl
treats as *create-time* — the BNK line (2.3 ↔ 2.4), the FLO namespaces, the
cluster network mode — are refused by the preflight gate and by `bnk up`
itself on an applied workspace: tear down first, then change them.

## Upgrading BNK

Bump `ROKSBNKCTL_MANIFEST_VERSION` within the same line and sync. The manifest
chart is re-pulled, the `CNEManifest` updated, and FLO rolls the components.
Watch the `bnk-up` log's readiness gates as in Step 4.

## Upgrading the runner

Bump `runner.tag`. Every roksbnkctl release ships a matching runner image with
its embedded Terraform, so the CLI and the HCL never skew. Read the roksbnkctl
changelog for migration notes before crossing a major version.

## Re-syncing

Safe at any time (Step 5). A no-op sync takes a few minutes: the gates plus a
`terraform plan` that finds nothing to do. To avoid the churn on every Git
change, keep the Application on manual sync — which is also what makes
**Sync** the approval step.

## Sync windows and who may sync

The `bnk` AppProject defines a `bnk-operator` role that may `get`, `sync` and
read `logs` but not edit the Application. Bind your operators' group to it
(`groups:` in the project, or Argo CD RBAC), and consider a `syncWindows` block
to allow syncs only in a maintenance window — the project file has one
commented out.

## A stuck apply

Every hook has `activeDeadlineSeconds` (`timeouts.*`): `bnk-up` defaults to
two hours. When the deadline passes the Job fails, the trap writes
`outcome: failed`, and the Application turns Degraded. Terminating the Argo CD
*operation* does **not** kill the Job — Kubernetes keeps running it, and the
Terraform state lock is held until it exits. If you must stop it early:

```bash
kubectl -n bnk-sm-cli delete job bnk-up            # then, if the lock is stuck:
kubectl -n bnk-sm-cli create job --from=job/bnk-init unlock-shell   # any runner pod with the PVC …
# … and inside it: terraform -chdir=/work/.roksbnkctl/sm-cli/state/tf-source/embedded-terraform force-unlock <id>
```

then **Sync** again.

## One run per workspace

The PVC is `ReadWriteOnce` and Terraform locks its state, so two syncs of the
same Application cannot run concurrently — Argo CD serialises operations per
Application anyway. Different workspaces are independent.

## Rotating the API key

Update the `bnk-secrets` Secret (or the External Secrets source). The next
hook pod picks it up; nothing is cached on the PVC except the `config.yaml`
that `bnk-init` rewrites on every run.

## Moving the state off the PVC

roksbnkctl supports a COS (S3-compatible) remote state backend with native
locking. Today it is enabled in `config.yaml` (`state.backend: s3`) rather
than by environment, so an env-built workspace keeps its state on the PVC.
Back the volume up, or wait for the `ROKSBNKCTL_STATE_*` override tracked in
the repository's roadmap.
